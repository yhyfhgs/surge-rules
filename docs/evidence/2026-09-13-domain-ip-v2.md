# Domain/IP routing v2 — 2026-09-13

## Scope and decision basis

The user approved implementation of the v6 plan and the concurrent documentation
cleanup. This migration retains 35 list names and splits 17 IP lists out of
mixed owners. All domain sets precede IP sets; each stage orders Reject, service
proxy, region and DIRECT. SYSTEM sits with non-IP DIRECT, and FINAL remains
proxy fallback. The manifest, not independently maintained tables, controls
runtime order and modifiers.

Baseline: `9ebce49d8644dbe982fdcddfc62eb46296a7b277`, 142,212 source rules.
The implemented sources contain 140,282 rules: 129,062 domain and 11,220 IP
rules. Counts exclude built-in rules and the profile's FINAL. The net reduction
is 1,930 rules; splitting or moving a rule is not counted as newly acquired
coverage. Unchanged lists were checked and retained rather than padded with
unreviewed upstream candidates.

## IP scope and readmission

StreamingIP shrinks from 1,983 entries to 21 verified or narrowly bounded Netflix
network entries. Official network documentation names AS2906/40027/55095. Fresh
ARIN/RIPE records support full ranges or precise returned subranges; a response
for one part is never extrapolated to the complete old CIDR. Historical cloud
and ISP cache ranges without adequate service evidence are quarantined.

Fresh registered ownership re-admits five AI CIDRs, two Meta ranges and four X
ranges that the ASN database alone did not fully cover. Missing ASN data was
not treated as reassignment. Registered ownership and an ASN label do not prove
that every application using a network has the same semantics.

TelegramIP is the exact current official 14-CIDR set, equivalently collapsed to
11 entries. Extra historical ASNs, broad ranges and backup addresses are held
outside matching. GamesIP retains eight directly allocated Blizzard /32s;
33 old cloud/ISP probe addresses lack a current dedicated binding. JapanIP
removes five whole-operator ASNs while retaining LINE/LY CIDRs and JP fallback.

`config/ip-review-exclusions.json` records 2,013 excluded source shapes and
specific fresh readmissions. It is an anti-reentry control, not a declaration
that the excluded addresses are dead. Regions subtract the complete DIRECT
protection sets in the manifest; exact interval analysis evaluates the effective
sets, including MMDB selectors, before reporting intersections.

ChinaIP is rebuilt from the locked 0087bb74e91b snapshot. Five reviewed CN ranges
are added, three foreign ranges removed, three previously approved HK ranges
retained, and seven new uncertain ranges withheld. Its 11,067 prefixes reproduce
the locked address-set hashes. `include_cidr` cannot bypass exclusion guards;
`--write` now refuses mismatched expected counts/hashes. Source input no-resolve
validation is separate from output matching parameters.

## Guarded domestic and expiry review

ChinaDomain's incremental workflow found 300 new candidates after ownership
filters. Two attempts resolved 202/300 and 201/300, below the existing 70% gate.
The source remains at 106,962 entries; the gate was not lowered and uncertain
rows were not admitted. The new additions-only path accepts only KEEP verdicts,
retains the existing layer, and prevents same-day retries from advancing drop
hysteresis.

A complete 21,906-value manual-domain sweep exposed defects in the old liveness
prober: executor queue time was counted as network timeout, and failed DoH could
be combined with missing delegation information to claim expiry. No deletion
was made from those results. The corrected probe uses a bounded curl transfer,
requires two clean NXDOMAIN responses plus authoritative confirmation, treats
parking as a hint, and spaces confirmatory observations by at least 24 hours.
Private/fake-IP answers are no longer independently labelled GFW evidence.

The corrected DNS-only sweep recorded:

| Result | Count |
|---|---:|
| DOH_ALIVE | 16333 |
| DOH_NXDOMAIN | 1216 |
| DOH_NODATA | 3973 |
| DOH_ERROR | 64 |
| DOH_SERVFAIL | 320 |

No domain reached the confirmed-expiry threshold. NXDOMAIN observations include
host-level/namespace questions; they are not proof that an entire suffix is
unused. Live local DNS interception also prevents interpreting anomaly labels
as independent censorship evidence. The user should not read this release as a
claim that every possible subdomain is live or that all suspected expiry is
resolved.

## Tool and profile contracts

The engine uses actual MMDB records and explicit DNS states. Pre-resolved
addresses can match no-resolve rules; an earlier skipped no-resolve rule is not
revisited after a later lookup. Successful/failed DNS observations, first A/AAAA
records, SNI/Host and mixed-family exclusions are tested. Missing observations
return an incomplete result. Existing negative-domain witnesses are explicitly
marked domain-stage rather than supplied with invented DNS answers.

Private profile preparation updates Rule, ordered DNS mappings and the four
DIRECT memberships across the Payment/download/game policy paths. Proxy and
certificate definitions remain unchanged. Unknown public lookups use encrypted
proxy DNS; known DIRECT services use domestic DoH; PrivateLAN uses system DNS.
All proxy servers reachable on the tested DNS paths are IP literals, preventing
the documented bootstrap cycle. No certificate verification was disabled.

Mihomo uses v2/revision-specific cache paths, explicit IP providers and the same
logical exclusions. Private profile generation is idempotent. Tests run with
TUN disabled and do not change system proxy settings or policy selections.

  download.microsoft.com and the synthetic Blizzard host show the same SSL

  responds on both paths. These probes do not certify login, payment, playback
  or a completed authenticated OneDrive synchronization.
- 4,750 scenario assertions, 84 adversarial harness assertions, engine/static
  self-tests, v2/expiry regressions, source sorting and Clash parity pass.
- Static audit has no P0/P1/P2, three existing P3 information items and zero
  unused exemptions. Full MMDB analysis rejects active shadows, unsafe splits,
  cycles and unbound/empty selectors; the final release gate reruns it.

Recent-request buffers collected during this work are dominated by diagnostic
queries. They cannot establish a daily FINAL-rate or performance improvement.
DNS/family semantics and correct ownership take precedence over forcing FINAL
counts to zero. Record post-activation runtime results separately from Git/CDN
publication.
